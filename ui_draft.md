# UI — наблюдения и черновики экранов

## Общие наблюдения

**Мобильный first.** Pera Wallet — телефон. QR сканируется телефоном. Значит основной сценарий:
пользователь держит телефон, открывает сайт в браузере на том же телефоне, там же переключается
в Pera Wallet. Десктоп вторичен.

**Два режима ввода равнозначны.** Загрузка .stl и текстовое описание («найди benchy») —
не основное и дополнительное, а два параллельных пути. UI не должен делать один из них «вторым
классом». Разделитель «или» визуально должен находиться по центру.

**Инструкция агенту — вместе с вводом модели, не отдельно.** Сейчас в architecture.md
«инструкция для выбора принтера» звучит как отдельный шаг. Но пользователь мыслит холистически:
«хочу напечатать benchy, подешевле и сегодня». Оба аспекта надо собрать на первом экране.

**Слайсинг + опрос принтеров занимают время.** Пользователь должен понимать, что именно
происходит и зачем. Прогресс-бар с двумя фазами («анализируем модель» → «собираем предложения»)
лучше, чем один спиннер.

**Экран предложений: главный вопрос — почему.** Пользователь не просто хочет увидеть список —
он хочет понять, почему агент выбрал именно этот вариант. Объяснение LLM должно быть
коротким, человекочитаемым, и стоять рядом с выбором, а не внизу мелким шрифтом.

**Session wallet — нетривиальная концепция.** Пользователи Pera Wallet понимают «переводы»,
но не «сессионный кошелёк агента». Нужно объяснить одним предложением:
«Вы пополняете временный кошелёк, агент оплатит заказ сам — остаток вернём».

**Вау-момент после пополнения.** Пользователь нажал «подтвердить» в Pera Wallet — и дальше
ничего не делает. Агент сам платит, ждёт подтверждения, запускает печать. Это должно ощущаться
как магия: счётчик секунд, tx_id, ссылка на AlgoExplorer — всё появляется автоматически.

**Прогресс-экран — главная «награда».** Это то, ради чего всё затевалось. Температуры,
процент, время — максимально лаконично и информативно. Адрес получения рядом.

## Открытые вопросы

1. **Что показывать, если принтер офлайн во время печати?** Нужен ли fallback?
2. **Нужна ли история заказов?** Для хакатона — нет. Для MVP — да.
3. **Что если пользователь закрыл вкладку после авторизации бюджета?** Сессионный кошелёк
   с деньгами «завис». Нужен таймаут и возврат средств по истечении.
4. **Ввод адреса возврата.** Куда возвращать остаток сессионного кошелька? Нужно спросить
   у пользователя его основной Algorand-адрес на шаге 5 (или он может ввести его заранее).
5. **Инструкция агента при ручном выборе модели (загрузка STL).** Пользователь загрузил файл
   и не ввёл инструкцию — нужен дефолт, например «выбери наилучшее соотношение цена/время».
